SORT 2.29.0 - STORE-PREPARATION TEST BUILD
======================================
This is the COMPLETE extension, not a patch. It is not Store-approved or a
completed compliance package. The separate offline support viewer is unchanged.

INSTALL SAFELY (LEON'S UNPACKED INSTALLATION)
1. Finish recordings, uploads and exports. Export important recordings to .sortz
   and verify the downloaded files. Keep a backup of the previous source folder
   and a secure record of your settings/credentials. A source-folder backup does
   NOT back up Chrome profile storage. Never uninstall the old extension before
   backing up recordings: uninstalling can remove its local data.
2. Extract this ZIP to a temporary folder. Replace the runtime files in the SAME
   unpacked extension directory already loaded in Chrome; do not load a second
   copy or move the original directory. Keeping that location preserves the
   unpacked extension identity and associated profile storage in normal use.
3. In chrome://extensions, reload SORT. Verify version 2.29.0 and no errors.
4. Refresh or reopen existing web tabs. This is REQUIRED: an old page-world
   WebSocket hook can remain installed until the page navigates/reloads.
5. Check your recordings and Settings before trying a live work session. If you
   instead use a separate Chrome test profile, configure it independently and
   import only safe test recordings. Do not run both builds on the same call.

SETTINGS AND CREDENTIALS
- Enter the shared call-state token in Settings once per Chrome profile. Leon
  supplies the SAME token personally to each authorized user. Do not embed it in
  release files, source history, screenshots, support messages or public links.
- The uploaded audit source had a redacted call-state URL, so this build also
  accepts that endpoint in Settings. Enter the real JSON call-state endpoint,
  not a CallHub web page. Existing locally saved URL/token may already appear;
  verify rather than overwrite them blindly. Supply your matching Sipgate name.
- The non-secret endpoint can optionally be fixed in defaults.js later; leave
  the token local. Never use an endpoint URL containing a secret as a packaged
  default. HTTPS should be used for the call endpoint wherever available.
- Enter each user's company email and their own Odoo API key. Use a suitably
  restricted Odoo account/key. Test call connectivity and ticket lookup.
- Credentials persist in this profile's IndexedDB without application-level
  encryption; they are not Chrome Sync settings. Local profile access can reveal
  them. A shared token offers no per-user revocation; the name filter is not an
  authorization boundary. Endpoint-wide exposure remains a server-side issue.
- 'Remove saved tokens' clears the Odoo and call-state keys, not the other
  settings or recordings. It disables configured call polling until a token is
  saved again. It does NOT revoke either key on its server. Verify after use.
- A non-placeholder token existed in Git history in the supplied audit ZIP.
  If still active, revoke/rotate it at the service and distribute the replacement.
  Omitting .git from this build does not undo previous exposure.

WHAT CHANGED
- No call-state token in packaged defaults; local token/endpoint Settings and a
  remove-saved-tokens action. Settings loading errors cannot silently blank keys.
- Worker message access is restricted by extension-page role. Content scripts
  cannot request full settings or invoke privileged operations. Extension local
  storage is restricted to trusted extension contexts; this is not encryption.
- No WebSocket payload buffer before recording starts or after recording stops.
  Payloads during an active recording are still recorded without new redaction.
- Cancelling/failing/timing out the Chrome sharing picker cancels ALL recording:
  no timeline-only fallback. 'Stop sharing' also stops/saves the timeline.
  Concurrent stops are serialized. Force-closing a capture window stops the
  timeline, but may lose/truncate video: use SORT Stop/Chrome Stop sharing.
- Removed unused webRequest and web-accessible page declarations. desktopCapture
  and broad host access are retained for the current cross-tab recording design.
- Update-ready notification/popup with 'Restart SORT now', 'Later' and a manual
  check. Restart button checks known active calls, recording, picker, saving,
  exports/downloads and open working pages. Close working pages to enable it.
  SORT reloads for an update only after an explicit click. Chrome can still apply
  updates independently when idle or restarting. 'Later' is not a permanent veto.
- Manifest is the sole manually maintained version. Original icons and the
  five-minute reminder behavior are preserved.

AUTOMATED CHECKS VS. REMAINING WORK
Source syntax, mocked security/recording/updater flows, full mocked worker startup
and reminder/diagnostic regressions were checked. These do not substitute for a
live Chrome run, actual backend access, cross-platform tests or Store-to-Store
updates. No live browser or Store approval is claimed for this package.

Upload still uses http://roupload.gdbz.network over the company VPN. HTTP service
and VPN-only transport remain unresolved for Chrome Web Store data-handling
compliance; this package does not certify them. No proxy or HTTPS upload service
was added. No complete new privacy disclosure/consent flow was implemented.
Before distribution, settle retention/deletion, access controls, lawful purpose,
training/use of recordings, user disclosure/consent and the privacy policy/Store
submission. Broad recording and live raw WebSocket payload capture still need
explicit privacy review. Unlisted Store availability does not replace access
control or policy review.

FUTURE RELEASES: AUTOMATIC METADATA, NO SECOND VERSION NUMBER
Keep the supplied build-sort-release.py OUTSIDE the extension folder. Python 3.9+
(with no extra packages) is needed only by the maintainer, not extension users.
After updating source and increasing version ONLY in manifest.json, run:

  python build-sort-release.py "PATH_TO_SORT_FOLDER" --output "SORT-release.zip"

Use python3 instead of python if required on your machine. Use a new output path;
the helper refuses to overwrite an existing ZIP. It regenerates build-info.js,
packages the reviewed runtime whitelist and optional TEST-GUIDE.txt, and checks
ZIP content. It omits Git, audit files, tests and unrelated files. If runtime
files are added, update the helper's whitelist deliberately. Update this guide
for future releases; it is specific to 2.29.0.

The fingerprint covers sorted top-level JS/HTML/JSON files excluding the generated
build-info.js, with filename/NUL/content/NUL hashing. It is a diagnostic identity,
not a signature or full integrity check for assets/libraries. The printed ZIP
SHA256 covers the final package. Literal-key checks catch common mistakes, not
all secrets: manually review source, endpoint URLs and bundled assets before
shipping. No JavaScript tests or live Chrome tests are run by the release helper.
Upload the complete ZIP to the SAME Store item with an increased manifest version
only after validation and resolving the submission/privacy requirements.
